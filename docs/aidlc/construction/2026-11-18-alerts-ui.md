# Construction Plan: In-app alerts UI

**Spec:** [docs/aidlc/inception/2026-11-18-alerts-ui.md](../inception/2026-11-18-alerts-ui.md)
**Date:** 2026-11-18

Builds on the notification service ([B06](../inception/2026-11-18-notification-service.md)), which is already in this branch:
the API, the `Notification` rows and `src/api/notifications.ts`. B07 adds no endpoint and changes no rule in B06.

## Design

### Deviations from the spec, adapted to the real B06 API

| Spec assumed | Built | Reason |
|---|---|---|
| `title` and `body` | `message` (one line, up to 300 characters) | B06 has no title or body. |
| Critical by `kind` in `CRITICAL_KINDS` | Critical when `severity === "critical"` | B06 sends `severity`. The kinds constant is dropped. |
| `POST /notifications/read-all/` (not called) | Not built | B06 has no read-all endpoint. Mark all read was already a non-goal. |
| Poll `?unread=1` and the count | Poll `?unread=true`, the full list (50 newest) and the count | The Alerts page shows read rows too, so it needs the full list. All three update together, so one mark-read changes the page, panel, banner and badge at once. |
| Bell name "1 unread notification and 2 items need attention" | Same wording, with singular and plural forms | Follows the spec. |

### Frontend (`frontend/src/`)

- `features/notifications/useNotificationFeed.ts`: `NOTIFICATION_POLL_MS = 30_000`. The hook polls the three calls.
  It skips a tick while the tab is hidden or a poll is still running. A shown tab refreshes at once and restarts the timer.
  A 401 or 403 stops polling. Any other failure keeps the last lists and sets `refreshFailed`. The timer and the
  visibility listener are cleared on unmount, which happens on sign-out.
- The hook runs in `StaffSession` (`StaffProvider.tsx`) and is exposed as `notifications` on `StaffState`.
- `features/notifications/NotificationBell.tsx`: the bell is a button with `aria-expanded` and `aria-controls`. Its badge is
  unread plus `attention.length`, shown up to `99+`. The panel lists 10 unread rows. Escape and a second press close it.
  Route changes close it.
- `features/notifications/CriticalBanners.tsx`: unread critical rows, at most 3, each `role="alert"` with Acknowledge.
  A line gives the overflow count and links to the Alerts page.
- `features/notifications/NotificationList.tsx`: `NotificationRow`, `MarkReadButton` (its own error text), `FeedNotice`
  (the "Couldn’t update alerts" line).
- `pages/staff/AlertsPage.tsx`: All or Unread (`FilterBar`, `aria-pressed`), newest first.
- `StaffLayout.tsx`: the bell becomes `NotificationBell`, and `CriticalBanners` sits between the top bar and the page.
  The bell CSS moves to `Notifications.module.css`.
- `roles.ts`: `alerts` module, nav second after Overview, view for all five staff roles. `planned.ts` drops `/staff/alerts`.
  `App.tsx` gets the real route.
- Mocks: `test/fixtures/notifications.ts`. `mockApi.ts` already answers the B06 routes.

### Backend (`backend/apps/accounts/`)

- `permissions.py`: `"alerts": VIEW` for the five staff roles. It matches `roles.ts`. The notification endpoints stay on `IsStaff`.

## Test plan

- Backend: the ENDPOINTS table gets the notification list under `alerts`, so every role's access is checked.
- Frontend, automated: polling every 30 s with fake timers; no requests while hidden; one refresh on show; no overlapping
  polls; a 403 stops polling; a failed refresh keeps the list and shows the time; badge number, `99+`, and the accessible
  name; panel open and Escape close; banner shows, acknowledges, and the overflow line; mark read updates everything;
  failed mark read keeps the row unread; empty and loading states; the Alerts filters; the nav for all five roles.
- CI: the three check commands in `AGENTS.md`, run in full.
