# Inception Spec: In-app alerts UI

**Date:** 2026-11-22
**Author:** Kabir-Raj-01, drafted with Claude
**Bolt:** [B07](../bolts/B07-alerts-ui.md)
**Related backlog item:** #53 (builds on the [notification service](2026-11-22-notification-service.md))

## Problem

The staff bell only counts things computed in the browser. Server notifications (B06) need to reach staff, and
critical ones must not be missed.

## User stories

- As staff, I want a notification bell and alert banners for critical events, so that urgent items are not
  missed. (#53)

## Acceptance criteria

- [ ] The existing bell in `StaffLayout` counts unread server notifications **plus** the existing attention items in
      one badge; the dropdown lists both, server ones first, each linking to its page.
- [ ] Opening a notification marks it read; a "Mark all read" button.
- [ ] Unacknowledged critical notifications show as a banner at the top of every staff page, with **Acknowledge**
      (calls the B06 endpoint). It stays until acknowledged, across reloads.
- [ ] Polls every **30 s**, paused while the tab is hidden, refreshed on focus.
- [ ] `/staff/alerts` page lists my notifications with a read/unread filter; removed from `planned.ts`; visible to
      every staff role.
- [ ] Endpoints mocked in `src/test/mockApi.ts`; component tests for the badge, banner and acknowledge.

## Non-goals

- WebSockets/push. Sound or desktop notifications.

## Open questions

Proposed answers; the Product Owner confirms them at sign-off:

1. **Polling interval?** Proposed: 30 s, paused when the tab is hidden.
2. **An alerts page, or the bell only?** Proposed: both; the page replaces the placeholder.
