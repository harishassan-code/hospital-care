# Login Page (UI Landing) — Positive Test Cases
### CityCare — Sprint Task
### Prepared: October 06, 2026

| TC ID | Test Case Title | Precondition | Test Steps | Expected Result |
|---|---|---|---|---|
| TC-01 | Login page loads successfully | User navigates to the application URL | 1. Open the application URL | Login page loads within acceptable time with all elements visible |
| TC-02 | Page displays all required UI elements | Login page is open | 1. Observe the page | Logo, email/username field, password field, "Login" button, "Forgot Password?" link and "Remember Me" checkbox are all present |
| TC-03 | Successful login with valid credentials | User has a valid, active account | 1. Enter valid username/email 2. Enter valid password 3. Click "Login" | User is authenticated and redirected to the hospital dashboard |
| TC-04 | Login button is enabled when both fields are filled | Login page is open | 1. Enter valid username 2. Enter valid password | "Login" button becomes active/clickable |
| TC-05 | Password field masks input | Login page is open | 1. Click on the password field 2. Type a password | Characters are displayed as dots/asterisks |
| TC-06 | Show/Hide password toggle works | Password has been entered | 1. Enter a password 2. Click the "show password" icon | Password becomes visible in plain text; clicking again re-masks it |
| TC-07 | "Remember Me" checkbox retains session | User has a valid account | 1. Enter valid credentials 2. Check "Remember Me" 3. Log in 4. Close and reopen the browser | User session/credentials are remembered and user is not prompted to log in again |
| TC-08 | Login with email in valid format | User account exists | 1. Enter a properly formatted email (e.g., user@hospital.com) 2. Enter valid password 3. Click "Login" | Login succeeds without format validation errors |
| TC-09 | Login with username instead of email (if supported) | User account exists with username | 1. Enter valid username 2. Enter valid password 3. Click "Login" | Login succeeds |
| TC-10 | Field focus moves correctly via Tab key | Login page is open | 1. Click the username field 2. Press Tab | Focus moves to the password field, then to the "Remember Me" checkbox, then to the "Login" button in logical order |
| TC-11 | Enter key submits the form | Valid credentials entered | 1. Enter valid username and password 2. Press "Enter" key instead of clicking Login | Login is submitted and user is authenticated successfully |

| TC-13 | "Forgot Password?" link navigates correctly | Login page is open | 1. Click "Forgot Password?" link | User is redirected to the password reset page |

| TC-15 | Session token/cookie is generated on successful login | User account exists | 1. Log in with valid credentials 2. Inspect browser storage/cookies | A valid session token/cookie is created |
| TC-16 | Login page is responsive on different screen sizes | Login page is open | 1. Resize browser window / open on tablet and mobile viewport | All elements resize/reflow correctly and remain usable |
| TC-17 | Autofill/browser-saved credentials populate fields correctly | Browser has saved credentials for the site | 1. Open login page 2. Allow browser to autofill saved credentials | Username and password fields populate correctly and login succeeds |
| TC-18 | Loading indicator displays during authentication | Valid credentials entered | 1. Enter valid credentials 2. Click "Login" | A loading spinner/progress indicator is shown while authentication is processed |
| TC-19 | Login page displays correctly across supported browsers | Login page is open | 1. Open the login page in Chrome, Firefox and Edge | Layout, fonts and elements render consistently across all browsers |
| TC-20 | Successful logout returns user to login page | User is logged in | 1. Click "Logout" from the dashboard | User session ends and they are redirected back to the login page |
| TC-21 | System Administrator login grants access to the Hospital Network management module | An active System Administrator account exists (role = "Admin", e.g., admin@citycare.org) | 1. Enter admin@citycare.org and correct password 2. Click "Login" | User lands on the Admin dashboard with "Register Hospital" and "Manage Users" options visible per FR-02; no blood-inventory or request-entry controls are shown |
| TC-22 | Hospital/Blood-Bank Staff login scopes dashboard data to their own hospital only | Two hospitals exist in the system (e.g., "City General" and "St. Mary's"); user account is linked to "City General" only | 1. | TC-23 | Emergency/Clinical Coordinator login lands directly on the Emergency Request screen | An active Coordinator account exists | 1. | TC-24 | Login triggers an audit log entry with correct user, timestamp and action | A valid user account exists; auditor/admin has access to Audit Trail screen | 1. Log in as any valid user at a known time (e.g., 10:21 AM, Oct 6 2026) 2. As Admin, open the Audit Trail (FR-14) | A new entry appears recording the username, "LOGIN_SUCCESS" action, and a timestamp matching the login time within a few seconds |
| TC-25 | Session expires after the configured inactivity timeout and requires re-login | User is logged in and the session timeout is configured to 30 minutes | 1. Log in successfully 2. Leave the session idle for 30+ minutes 3. Attempt to navigate to the dashboard | User is prompted to re-authenticate via the login page; after re-entering valid credentials, access resumes normally |
| TC-26 | Login succeeds on first attempt after a previously failed attempt (no lockout yet) | Account has exactly 1 prior failed login attempt (below the lockout threshold, e.g., 5) | 1. Enter correct password on the 2nd attempt 2. Click "Login" | Login succeeds immediately; failed-attempt counter resets to 0 without any lockout message |
| TC-27 | Password reset link received via email successfully logs the user back in | User clicked "Forgot Password?" and received a reset email for jdoe@citygeneral.org | 1. | TC-28 | Concurrent login from a second device does not break the first active session's data | User is already logged in on Device A (desktop) | 1. On Device B (mobile), log in with the same valid credentials | Device B login succeeds and shows the correct role-based dashboard; Device A session either remains active or is handled per the defined session policy without data corruption |
| TC-29 | Deep-link redirect returns user to the originally requested page after login | User (not logged in) directly opens a specific URL, e.g., /requests/REQ-1042 | 1. Attempt to open /requests/REQ-1042 while logged out 2. System redirects to login page 3. Enter valid credentials and click "Login" | After successful authentication, user is redirected to /requests/REQ-1042 (the originally requested page) rather than the generic dashboard |
| TC-30 | Login API returns correct HTTP 200 response with expected payload structure | Valid credentials exist for a test user | 1. Submit login via the API endpoint (e.g., POST /api/auth/login) with valid email/password 2. Inspect the response | Response returns HTTP 200 with a JSON body containing a valid JWT/session token, user role, and hospital ID, matching the API contract in Section 2.4 |

**Summary:** 30 positive test cases — the first 20 cover generic page load/UI rendering, authentication flow, field behavior, accessibility and cross-browser checks; TC-21 to TC-30 are CityCare-specific, covering role-based redirects and data scoping (Admin, Hospital Staff, Coordinator), audit logging, session timeout, failed-attempt counter reset, password-reset-to-login flow, concurrent sessions, deep-link redirect preservation, and the login API contract.
